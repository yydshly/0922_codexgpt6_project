## 恒星交叉核对

来源：CDS VizieR [ESA 1997 Hipparcos 原版 I/239/hip_main](https://cdsarc.cds.unistra.fr/viz-bin/cat/I/239)，对比项目采用的 [van Leeuwen 2007 新归算 I/311](https://cdsarc.cds.unistra.fr/viz-bin/cat/I/311)。两边均使用 ICRS、J1991.25，不把不同年代的星位直接相减。

HIP 8102、16537、54035、87937、108870 共 5 个样本，最大方向差 **1.986 毫角秒**。视差差另行列出，不混作方向误差。20 毫角秒仅为导入坐标/单位的粗差筛查门槛，不是当前星位的精度承诺。

**这是不同归算版本的交叉检查，资料来自同一个 Hipparcos 观测任务，不是独立望远镜测量。** 未应用自行、岁差章动或地平转换，不能用作今晚地面星图。

- 原始记录和校验值：`data-sources/stars/hipparcos-1997-checkpoints.tsv`、相邻 provenance 文件。
- 逐星结果：`public/data/stars/validation.json`。
- 复算：`npm run validate:stars`；SHA、历元与样本数检查失败会返回失败状态。

## 参考设备与方法

Chrome/153.0.8010.53，Windows，ANGLE (Intel, Intel(R) UHD Graphics (0x0000A788) Direct3D11 vs_5_0 ps_5_0, D3D11)。浏览器报告 32 个逻辑处理器、16 GB 内存档位；窗口 1600 × 1000、DPR 1、页面可见。它是本次固定的无头浏览器配置，不代表所有用户电脑。

基线及实时播放各测 6 秒；每次场景就绪 1 秒后采样 3 秒。邻星空间 → 同星方向 → 银河系 → 银河系之外 → 太阳系，重复 4 轮。帧率采用实际 renderer.render 完成时刻；帧间隔 P95、资源数、图层开关、日期和设备原始记录均随报告保存。每次资源快照前强制垃圾回收。最终采样期间没有运行构建或测试。

复测工具：`node scripts/measure-performance.mjs .cache/performance-latest.json`，需本机预览 4180 及浏览器调试端口 9223；只在 `?diagnostics=1` 记录绘制信息，正常页面不启用。

最终各采样窗口为 **29.16–30.04 fps**；太阳系实时播放 **29.25 fps**。原有绘制节奏约 30 fps，本轮仍有低于 30 fps 的采样，**尚未满足严格的 ≥30 fps 验收要求**。未用四舍五入把它记成通过，也未把此短测当成长时间流畅度保证。

修复后 document 的镜头 keydown 监听每次为 1，重复访问同类场景的事件监听数量稳定。减少选项约降低该页 90% 的 DOM 数量，但这不等于帧率提升 90%。

仍待追踪：太阳系 DOM 节点 4335 → 4359；GC 后 JS 堆 13.69 → 15.73 MiB。可能包含缓存、历史记录、浏览器内部保留或未释放引用，当前证据不足以判定来源。**不宣称没有内存泄漏**。Three 资源计数只反映当前实例，不是驱动显存字节；后续需更长时段和堆引用分析。

原始前后对照：`public/data/validation/performance-baseline.json`、`performance-final.json`。基线未加实时播放窗口，比较主要使用同名静止场景；本轮没有声称实时播放的前后提升。未捕获运行异常。

## 第二批 · 绘制节奏与共享几何清理

原因定位：主全景和宇宙画布此前用 `now - lastFrame < 30` 跳过刷新，将绘制节奏限制在约 30 fps；延迟一次就进一步低于目标。现在跟随浏览器刷新，不按帧数累加公转或自转。历表仍按统一日期取样，示意运动继续使用经过的时间；本轮不修改天体周期和轨道数据。

第二处是 Sprite 的共享几何。Three r180 的 Sprite 使用模块级几何对象；本项目此前只释放网格、线和点，宇宙页的 Sprite 也只释放材质与贴图。堆引用链显示共享几何的属性关联着旧渲染器的缓冲与画布。现统一在销毁渲染器前清理 Sprite 几何、材质和贴图，并去重共享资源。几何的数据仍可由后续场景重新上传，不删除仍使用的对象。

诊断注意：查询浏览器的 detached nodes 会让调试器本身持有返回节点，不能把这种观察造成的引用全部归咎于应用。复核快照不先调用该接口；复现工具 `node scripts/qa/scene-retention.mjs`，快照只保留在本地 `.cache`，不上传整个浏览器堆。

### 40 次切换复测

同一参考设备、窗口和图层配置，按相同五场景顺序重复 8 轮（40 次切换），基线与实时播放各 6 秒、各场景 3 秒、结束后太阳系再采样 10 秒。此期间未并行运行构建或自动测试。原始数据与判据：`public/data/validation/performance-refresh.json`。

| 项目 | 第二批复测结果 |
| --- | --- |
| 太阳系各采样窗口 | 47.74–55.47 次绘制/秒 |
| 太阳系实时播放 | 49.00 次绘制/秒 |
| 结束后 10 秒窗口 | 50.76 次绘制/秒 |
| 太阳系每次返回的 DOM / 监听 | 4,335 / 651，八轮一致 |
| 星空方向每次返回的 DOM / 监听 | 2,217 / 300，八轮一致 |
| 主画布注册实例 | 每次 1；结束创建 57 / 销毁 56 |
| document 镜头监听 | 每次 1 |
| 同类场景几何、纹理、程序计数 | 八轮一致 |
| 运行异常 | 0 |

**这里测量的是 CPU 完成 render 调用的提交速率，并非 GPU 完成呈现或用户屏幕的实际帧率。** 这台无头浏览器配置的所有提交采样达到 ≥30；取消强制跳帧会增加绘制工作，实际功耗、高刷新率屏幕、长时间操作与其他电脑仍需实机验收。不把此结果写成全设备性能保证。

原先每轮多 6 个 DOM 节点的增长已经消失。GC 后 JS 堆从 13.71 MiB 到结束 15.89 MiB，暖机、JIT 和应用缓存仍影响该指标；第 4 次与第 8 次返回太阳系分别 15.61、15.83 MiB。此范围内没有相同场景的节点/监听线性增长，但仍不以短测证明所有内存都无泄漏。

75 个测试文件 / 311 项通过，新增共享 Sprite 几何、材质、贴图去重释放与后续复用检查；生产构建通过，包体警告仍在。

当前剩余：参考环境的绘制吞吐和此次节点残留修复完成；仍需汇总历表/插值/物理模型的科学证据及缺口，完成真实设备的交互验收、用户验收，再按授权发布。第一批的“掉帧、DOM 增长待追踪”由本节更新；R09 总验收未完成。


### 堆引用复核

未先查询 detached nodes 的两份快照：修复前经过 3 次太阳系/宇宙往返，仍有 5 个 Three 画布节点；修复后经过 8 次往返，仅剩当前 1 个 Three 画布。两个样本的往返次数不同，不能当作每次切换节省固定内存的测量，但支持旧画布残留已消除。仅归档去除浏览器其他内容的计数摘要：`public/data/validation/scene-retention.json`。

快速往返脚本的个别立即 GC 快照还会看到暂存事件监听（651 或 957），没有随循环累积；另一次固定等待/40 次切换采样的同场景监听均稳定。不要将两种不同采样时机的数字混用为同一指标。更长时段、其他设备与真实屏幕呈现仍留待实机验收。
