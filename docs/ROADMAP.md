## 近期实施优先级

当前先补全宏观全景的图层、小天体轨道与空间环境，再推进近景学习路径；地月分步讲解后移。第一批实施与边界见 [宏观补全](MACRO-EXPANSION.md)。具体步骤及验收条件见 [当前交付与下一步](CURRENT-BASELINE.md)。下文 P0—P6 保留为长期工程依赖，不表示下一轮立即扩充天体或启动游戏功能。

## P0：先统一可扩展的科学接口

**输入与依赖。** 保留当前目录、月份数据、验证报告和十体初始条件。现有 `BODY_IDS`、按固定顺序排列的 `StateFrame`、五个固定父星的 `useOverviewSatellites` 适合当前规模，继续逐处添加索引容易造成目标混淆；`NBodySystem` 本身已按 GM 数组长度工作，但应用层仍有十体假设。

**接口迁移。** 新增版本化接口与适配器，先让旧数据通过新接口输出，不一次重写积分器。

| 接口 | 必备内容与约束 |
| --- | --- |
| `CatalogEntry` | 稳定字符串 ID、类别、父体关系、名称、来源、半径或形状参数；区分资料、历表、实验能力。未知参数可明确为空，不能补成零 |
| `StateBatch` | `targetIds` 与双精度位置/速度数组、TDB 历元、坐标轴、原点、单位、提供器版本、质量状态；不依赖数组下标猜目标 |
| `StateProvider` | 覆盖范围、同步缓存取样、异步预载、取消/过期请求处理；结果区分 ready、loading、out-of-range、error |
| `DynamicsModel` | 明确参加引力的对象、GM、中心或系统质心、所代表的成员集合、积分策略；与观测目录分开 |
| `PresentationState` | 科学状态的派生副本，包含距离压缩、显示半径、镜头与说明性外观；不能反向写入科学数组 |

中心与质心必须成为机器可检查的字段。把行星系统展开为母星与卫星时，不能保留系统总 GM 再叠加卫星 GM；不能拿母星中心初值配系统质心的验证目标。加载模型前检查代表的成员是否重叠、GM 对应何种目标、同一批次的坐标与历元是否一致。观测坐标的合成必须是同一时刻的“父体状态＋相对状态”；父子状态不得来自不同日期。

第一步保留十体专用适配器和原数组顺序，令其继续喂给现有验证脚本。渲染、选择、标签和家族列表逐渐转为按 ID 查询；提供器注册表替换四组硬编码 hook。数组更新与 Worker 消息同时携带 ID 顺序、实验版本和请求代号，旧响应不得覆盖新实验。

**验收。** 原 19 个对象的同历元状态与旧适配器一致；物理基准不退化；中心/质心误配与质量重复计入被拒绝；跨月、跳日期、切模式、加载失败与重试不显示旧状态。改变展示比例、镜头、光照后，科学数组及科学读数保持不变。

**边界。** P0 不扩充物理参与者，不借重构改变默认积分方法，也不把所有目录对象自动送入多体计算。

## P1：补齐两组主要卫星

**输入。** 目标为天王星的米兰达、艾瑞尔、乌姆柏里尔、泰坦妮娅、奥伯龙，以及土星的土卫一、三、四、五、八。现有土卫二、六保留，共新增十颗；全部验证通过后由 19 增至 29。

**依赖与实现。** 依赖 P0 的注册表、身份和中心守卫。沿用 [卫星采集脚本](../scripts/prepare-satellites.py) 的内核裁切、按父星与月份分包、Hermite 插值和校验值机制，扩展为数据驱动配置。新增目标使用父行星中心几何状态，记录实际使用的内核版本、时间范围和物理参数来源；不预先假定某个内核一定覆盖所需年份或全部目标。

**接口迁移。** 加入目录与 provider 配置即可出现家族菜单、全景叠加、近景和参数面板。地面观测的几何位置、外观姿态示意、瞬时开普勒参考线分别标记。姿态或形状资料不全时，仍可显示经验证的位置，但必须保留外观示意说明。

**验收。** 每个目标逐独立中点验证，并补充四分之一点、固定随机时刻与月界检查；同时检查位置、速度、轨道平面及顺逆行。位置先沿用现有观测的 **1 km** 门槛，新增速度门槛建议为 **1×10⁻⁴ km/s**，写入报告配置；这些是拟定的插值集成门槛，不是源历表的绝对精度保证。不通过则缩短对应目标的采样间距，不能沿用所有卫星相同的固定采样间隔并跳过检查。计数、失败状态、真实比例及整圈轨道取景一并验收。

**边界。** 此阶段只扩展历表观测。300 秒步长的十体报告不能证明紧密卫星系统也足够准确；如要独立推演某个家族，须另建模型与步长收敛报告。

## P2：五颗矮行星与卡戎

**输入与依赖。** 基于 P0/P1，接入谷神星、冥王星、妊神星、鸟神星、阋神星和卡戎。前五颗已有静态资料，前三个目标已接入历表、目录与外观；其余三颗通过后候选动态数为 35，不将既有图鉴条目再算一遍。

**接口迁移。** 原点关系不能只支持“行星—卫星”。允许太阳系质心状态、相对矮行星状态及系统质心状态，并显式组合。冥王星中心、卡戎中心、冥王星系统质心是不同状态目标；能够取得哪个，就声明哪个，不能用系统质心假扮冥王星球体中心。妊神星等非球形对象保留半轴、体积等效半径与形状示意的区别。

**验收。** 按目标核查供数身份、覆盖、中心语义、质量/GM 来源和插值报告；相对冥王星的卡戎位置与合成后的全局状态分别验证。大视野下检查原点重定位与 GPU 精度，保证近景缩放不抖动、不会把轨道压回黄道平面。若某目标只能取得近似状态、参数不足或验证未通过，保留资料入口，不计入已验证动态目标。

**边界。** 暂不补齐这些天体的全部卫星、环或精密自转模型；动态观测能力也不自动赋予其可靠的交互引力模型。

## P3：代表小天体与分层供数

**输入与依赖。** 依赖统一 provider 和按目标出具的质量报告，分批接入灶神星、67P、贝努、龙宫等代表对象；最终范围由权威数据覆盖和验证结果决定。已有灶神星、67P 的静态图鉴可复用。

**接口迁移。** provider 增加质量等级与有效窗口：重点目标使用经验证的稠密历表；远处大量对象可采用轨道根数或其他有明确误差范围的近似表示。按视野、选择目标和时间窗口加载，设置缓存与请求预算；图鉴元数据、远景点、近景形状分别加载。近似轨道须标记来源历元、适用时段和方法，不与权威历表混为一个质量类别。

**验收。** 对开普勒传播与固定间隔插值都做独立对照；近日点、高曲率与近遇区间加密抽查，过期根数不得继续声称真实当前轨道。测试按需加载、取消过期请求、缓存上限与目标机器的交互性能，先记录基线再确定资源预算。真实逐体小天体与随机带区示意分层显示、分别计数。

**边界。** 不以“全宇宙”或“所有小天体直接多体积分”为目标。彗星喷流、尾迹、非引力加速度和近距离复杂引力不能仅靠静态外观与二体轨道宣称已模拟。

## P4：参数沙盒与独立实验存档

**输入与依赖。** 由经验证的观测快照或用户新建对象生成实验副本，依赖 P0 的显式动力学模型。权威历表、原目录和内置验证报告保持独立。

**接口迁移。** 引入版本化 `ExperimentSnapshot` 与带时间戳的编辑命令，保存对象 ID、初始状态、动力学参与方式、参数、积分配置、来源版本和编辑历史。增删、改位置速度或参数作为完整事务应用；失败时返回最后有效状态。初版可用本地持久化与 JSON 导入导出，导入先校验版本、单位、数值和模型身份。

GM 是当前引力计算的直接输入，碰撞、燃料与推力还需要一致的惯性质量。实验须选定统一换算约定；不能强迫目录中四舍五入的公开质量与精密 GM 数字完全相等。用户编辑质量或 GM 时同步派生另一项，保留原来源值；质量很小的试验粒子若不反作用于主星，应以明确模型标志表示。

**验收。** 修改、重置、撤销或重新打开实验可复现相同状态；异步旧响应不覆盖新编辑；增删后数组索引、选择与轨迹不串位；不允许非有限数、非法 GM、未处理的重叠初值。编辑过的实验不继续显示为真实历表，其实时诊断与内置十体基准报告分开。

**边界。** 先支持有限数量、明确受支持的实验配置。300 秒仅是现有基准设置；紧密轨道、强扰动和近遇先做步长收敛与误差检查。预算不足时降实际倍率或暂停，不偷偷增大步长；失败后不能展示一个已推进一半的状态。

## P5：简化碰撞与合并

**输入与依赖。** 依赖 P4 的一致动力学质量、真实几何半径、事务和事件记录。先实现完全非弹性的球形合并模型，不做碎裂模拟。

**接口迁移。** 新增确定性的碰撞事件、合并后 ID 与父事件记录。检测使用科学空间中的真实半径和扫掠路径，不能使用为看清球体而放大的显示半径。基础步内部按局部相遇时间递归二分，直到接触时间与积分误差满足配置；多体同时接触按明确规则归并，避免数组顺序决定结果。

合并质量为两体质量之和，位置取接触时的质量中心，速度由总线动量除以总质量得到。若选择体积相加规则，则新半径按 `R³ = R₁³ + R₂³` 计算，并明确这是不可压缩体积的简化假设。相对动能损失记录为内部耗散；删除两体相互势能、引入新半径也会改变机械能账目，不能把合并前后总机械能差都归为积分误差。若不保存合并后的自旋角动量，明确不保证总角动量守恒。

**验收。** 将两类测试分开：无碰撞段检查积分收敛与守恒漂移；碰撞事件检查质量、线动量、接触时刻、耗散账目和确定性。覆盖高速穿越、擦边、初始接触、不同帧率与三体连续碰撞。细分上限耗尽时给出可恢复暂停，不能漏碰后继续。

**边界。** 这是游戏与实验可用的合并规则，不代表撞击热力学、碎片、潮汐破坏或真实天体内部结构。

## P6：飞船、推力、燃料与任务

**输入与依赖。** 依赖 P4 的实验与指令时序，以及适合飞行尺度的积分策略；需要碰撞/着陆事件时再依赖 P5。明确采用“历表主星＋试验飞船”还是“自洽多体＋飞船”，不要把强制沿历表运动的主星算进孤立系统能量守恒测试。

**接口迁移。** 增加飞船干质量、燃料、推力与姿态、控制参考系、机动指令和任务状态机。观测时钟、物理时钟与镜头动画分离；机动在精确的模拟事件时刻开始和结束，力与质量变化进入积分器，不能直接推动渲染网格。任务读取科学状态与事件，场景缩放只服务显示。

**验收。** 无推力时轨道与既定引力模型一致；理想机动与火箭方程或独立参考解对照；燃料不为负，燃尽、暂停、存档恢复及高倍率跨事件时行为确定。推进期间能量和动量预算计入推力、燃料及外部历表源。接近地表或执行短时机动必须缩短步长并验证，不能继承 300 秒基准的精度声明。

**边界。** 先做轨道飞行与少量任务。大气再入、复杂姿态控制、发动机热模型、精密着陆和导航级预测另立模型与验收，不作为这一阶段的默认承诺。

## 复验与交付要求

现有可运行命令如下。仅文档规划不需要重新生成数据；真正更改采集、插值或物理代码时执行对应检查。

```sh
npm test
npm run build
python scripts/prepare-satellites.py   # 修改卫星采集/采样配置后，重建并独立校验
npm run validate:physics             # 修改物理模型/积分器后，复验十体基准
```

新阶段增加的脚本应随代码提交，并在这里补充真实可执行命令。每批交付至少包含目录变更、数据来源与版本、覆盖范围、校验值、独立误差报告、失败行为及界面说明。报告分别给出插值差异、数值积分差异与模型差异；它们是不同向量比较，不能将误差模长相减来推导“真实模型误差”。科学与展示的边界在所有阶段持续成立。

## 产品方向与规则扩展

以下是候选产品分支，其完整玩法与产品闭环尚未实现，也不替代 P0—P6。真实观测已经可用；当前三维场景、天体选择、历表与独立 Worker 可以复用，角色、能力、经济和任务系统仍需建设。产品优先级属于设计判断，不代表市场成功或实现时间的承诺。

### 五种方向如何取舍

| 方向 | 主要体验 | 对当前底座的新增要求 |
| --- | --- | --- |
| 真实观测与教育 | 认识尺度、轨道与昼夜，用导览回答问题 | 内容组织、课堂任务、观察记录；最接近现有能力 |
| 科幻探索 | 驾驶飞船、探测资源、建立据点 | 依赖 P4/P6 的控制、燃料与任务；早期可先做节点间探索 |
| 仙侠星域 | 御器游历、宗门据点、灵力与星门 | 新增角色成长和能力规则；真实天体结构提供空间感，超自然效果明确为虚构 |
| 时空穿越 | 重返事件、改变选择、比较世界分支 | 检查点、事件回放和分支存档；需要先定义哪些状态随穿越改变 |
| 星球掌控 | 从调整轨道到经营世界，再到改变规则 | 按下述三层拆开，避免把治理数值当作真实物理结果 |

建议保留观测工具作为可信入口，另开一个小型可玩分支验证探索与选择是否有趣，再决定偏科幻还是仙侠。换皮不足以形成游戏；关键是玩家行动、成本、反馈与目标能否构成循环。

### 共享世界，独立规则与存档

共用天体身份、几何场景和来源资料；开始游戏时从指定观测历元复制世界初始条件，生成独立实例。能力只能改变该实例。返回真实观测重新读取 provider，不能把“移山”“挪星”后的状态写回权威数据。

建议在 P0 的目录和状态之上增加五个概念接口，名称是设计提案，并非现有代码导出：

| 概念 | 职责与现有接口的连接 |
| --- | --- |
| `Role` | 玩家身份、受控实体、资源与权限；引用目录 ID，不塞进 `BodyDefinition` |
| `Ability` | 目标条件、消耗、冷却、效果命令和事件；通过规则检查后进入 P4 命令队列，不能直接移动 Three 网格 |
| `WorldRules` | 指定动力学、时间、资源与胜负规则及版本；科学分支使用既有模型，幻想分支显式记录例外 |
| `Scenario` | 初始 `StateFrame`/世界快照、角色、目标、触发条件和可用能力；复用场景展示，独立管理任务 |
| `Save` | 世界 ID、规则版本、初始来源、当前快照、事件、随机种子和分支父节点；不同规则集禁止无检查地互相覆盖 |

物理、任务和视觉事件分别记录。神通若产生冲量、瞬移或改质量，须记作规则注入，并重建相应实验状态；不能将其造成的能量变化冒充积分误差。粒子、光效与镜头仍只负责展示。

### 两种时间与三层星球控制

当前日期跳转只是读取某个真实日期的历表，或重新初始化物理实验，并不是游戏时间旅行。穿越应区分“查看过去”“恢复检查点”“从过去另开分支”；后两者必须恢复角色资源、任务、随机状态与事件，而不只恢复天体坐标。第一版可选择分支时间线，暂不处理自洽因果悖论或相对论时空。

星球掌控分为三层：**物理参数层**修改质量、半径、轨道和速度，沿用 P4/P5 的校验与记录；**治理改造层**管理人口、资源、设施、生态等抽象数值，气候或地表变化只有模型支持时才声称可计算；**神通规则层**允许星门、结界、时间暂停等虚构能力，以消耗、范围和冷却形成约束。三层可组合，但界面必须说明操作影响哪一层。

### 首个可玩切片：一个角色，一次地月探索

建议从地月场景生成独立演示存档：控制一个角色，在跟随与自由镜头间切换，进入保持安全距离的观察区域，标记第一观察点，经传送门到第二观察点，完成任务并保存重载。同一个角色控制接口可以表现为探测器或御剑者；移动与空间跳转属于演示规则，不冒充真实飞船轨道。先验证近景、移动、空间跳转与任务闭环，不同时开发完整仙侠养成或轨道飞行教程。

天王星五卫星、土星新增五卫星及谷神星、冥王星与卡戎已接入；后续数据扩展仍需完善共同接口并逐体验证。可玩切片在共用基础就绪后并行推进，只取 P4 所需的最小快照、命令与存档能力，不必等待 35 个动态天体或完整沙盒。自由视角保留拖动回退；若加入鼠标锁定，设计明确的点击进入、退出与失败回退。

验收要求：角色不会穿入天体；观察点、跳转和任务只结算一次；暂停、重开与读档结果一致；无效目标被拒绝；存档分支互不污染；任何操作都不改变真实观测数据；玩家能区分真实日期、游戏时间和幻想规则。先验证这一循环，再依据实际试玩反馈扩展产品方向。

浏览器能力参考（核对日期：2026-09-22）：[MDN Pointer Lock](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_Lock_API) 支持第一人称视角的连续鼠标输入，但需用户手势触发，并检测兼容性和失败情况；[Three.js LOD](https://threejs.org/docs/pages/LOD.html) 提供按视距切换显示细节的基础。两者支持相关交互与渲染方案，不代表当前项目已经具备角色、地表或完整游戏系统。
