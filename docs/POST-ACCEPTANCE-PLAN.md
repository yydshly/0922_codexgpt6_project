# 认知版归档后的完整发展规划

规划日期：2026-09-26。状态：待启动的规划，不代表功能已经实现或获准全部开工。

适用基线：2026.09.26-r09.12，本轮验收通过并冻结。功能验收提交为 `3497f3d`，验收记录提交为 `3857b5e`。确认范围见 [验收记录](ACCEPTANCE-RECORD.md)。本文统一描述归档后的发展路线；旧工程路线、产品样机建议和 M0–M6 台账保留历史参考，不叠加成新的待办。

## 1. 目标与阶段边界

当前已经交付的是**认识真实太阳系**：看天体、运动、参数、来源和代表现象。下一步不是自动增加功能，而是确定它要帮助谁完成什么事。

- 若目标是更好地**理解真实太阳系**，先核对现有观测和课程能否回答目标问题；只有明确的知识缺口才启动科学或教学分支。
- 若目标是做**物理假设实验**，才考虑复制真实初值、改变条件并比较结果。任意修改星球没有独立的产品价值。
- 若目标是**驾驶与任务**，可直接基于真实观测状态建立探测器世界；不以天体编辑或天体合并为前置条件。
- 若目标是认识**人类如何进入太阳系**，先区分真实人造卫星/探测器轨迹、模拟卫星部署与完整火箭发射。它们不是天然卫星，也不自动由飞船驾驶功能覆盖。
- 若目标是**幻想或经营玩法**，先定玩法规则；它可复用三维场景和目录，不自动继承真实物理规则。

S1、S2、S3 是三个**候选能力包**，共 12 个工作包，并非已经确定的必经主线、12 次对话或固定工期。当前认知版已归档，尚未确定要启动哪个方向。

## 3. 先确定目标，再选择能力

启动任何开发前，先写清 **目标用户 → 他们要回答的问题或完成的任务 → 现有能力为何不足 → 最小可用场景 → 验收方式**。如果现有观测和讲解已足够，就不需要新增编辑、碰撞或飞船。

| 选择 | 何时有意义 | 必要前提 | 第一个可验收场景 |
| --- | --- | --- | --- |
| S1 可编辑实验（5 包） | 用户需要通过改变一个变量理解因果，或要玩“改变轨道”的沙盒 | 明确所问的问题、可对照的真实初值、支持范围、误差与恢复规则 | 调整地球初始速度，比较轨道并恢复；先用已有课程检验是否仍有理解缺口 |
| S2 碰撞与演化（3 包） | 用户确实要研究或游玩天体接触后的简化结果 | 已有可复现实验、物理接触尺寸、合并规则；说明模型限制 | 两个实验球体相遇、合并、回放并核对质量和动量 |
| S3 飞船与任务（4 包） | 用户要从观测者变成驾驶者，体验飞掠、入轨或交会 | 探测器状态、近景坐标、引力与推力模型、任务记录、基本撞击判定 | 无推力探测器绕目标运行；再加入推力和任务 |

**依赖关系：S2 依赖 S1 的可复现实验基础；S3 可从当前观测版独立启动，不依赖 S1 的任意天体编辑，也不依赖 S2 的天体合并。** S3 需要的飞船撞击判定可以单独实现。科学深化、教学和幻想方向也可单独排期。

只有选定方向后，才为对应工作包冻结目标设备、规模、工期和验收线；其余候选不计为当前欠账。

## 4. S1：可编辑实验（仅在明确物理实验目标后启动）

先指定一个用户确实想弄懂的因果问题，并核对现有运动课程与日期观察是否已经回答。若没有缺口，不启动本包。编辑控制每次尽量改变一个变量，解释显示变化与真实单位。

### S1.1 实验边界与状态接入

- 从现有十体物理基准开始，复制指定时刻的科学状态，生成独立实验 ID 和规则版本。
- 明确参与引力的对象、中心/质心、质量或 GM、坐标轴、单位和同一历元；展开卫星时不得重复计入系统质量。
- 按稳定对象 ID 接入 Worker、渲染、参数和选择状态。现有核心已支持按 GM 数组长度计算，重点是应用层身份、数量变化及消息一致性，不重写已有算法。
- 记录每个成员是历表初值、近似状态还是用户创建。缺数据拒绝创建并说明原因。
- 验收：原十体结果不退化；切换真实观测与实验互不污染；旧 Worker 响应不覆盖新实验。

### S1.2 参数编辑与重置

- 支持质量/GM、物理半径、位置、速度的带单位编辑，注明相对谁、采用何坐标。
- 第一版仅在暂停时编辑；记录编辑前后状态。编辑后预测失效并重新计算。
- 提供初始条件重置与未提交编辑取消。主星被删除、数值无效、初始重叠等情况有明确规则。
- 验收：数值与单位校验有效；质量和 GM 保持一致；显示缩放不改变科学参数；重置回到同一初值。

### S1.3 增删、复制与有限规模运行

- 新建和复制实验对象，删除对象后同步更新列表、镜头目标、轨迹和 Worker 状态。
- 使用受支持的模板与可解释的初始条件，不承诺任意参数组合稳定。
- 首轮按十体基准加少量测试对象实施；启动时冻结具体对象上限、时间范围和设备预算。没有测量前不宣称百万级规模。
- 在 S2 之前，接触或危险近遇暂停并说明，不允许静默穿过后继续给出貌似可靠的结果。
- 验收：对象身份不串位、失败能恢复、删除选中对象有合理退路；相同物理步数不受画面帧率影响。

### S1.4 实验存档与复现

- 保存初始条件、当前状态、已执行步数、规则/算法版本、步长、数据版本和编辑记录。
- 本地保存、导出、导入；存档包含必要初始状态，不能只存可能失效的数据链接。
- 损坏或不支持版本的存档拒绝加载并保留原实验；先做明确版本校验，不承诺兼容全部未来版本。
- 验收：保存后继续计算与重载后继续计算在规定误差内一致；重置、恢复与重新开始含义清楚。

### S1.5 对照、诊断与阶段交付

- 提供真实参考、未修改模型、修改后实验的区分与比较，显示轨迹和关键参数差异。
- 分开解释“人为改动的结果”“简化模型与历表的差异”“数值离散误差”，不将三者混成一个误差值。
- 对冻结案例进行步长收敛、守恒量和不同播放倍率检查。计算跟不上就降低实际推进速度。
- 首个验收实验：复制基准 → 修改地球初始切向速度 → 观察轨道变化 → 保存恢复 → 重置回原状态。
- **不做**：碰撞合并、飞船、任意天体全部导入、通用百万体求解、真实气候响应。

## 5. S2：碰撞与演化（仅在相遇结果是目标体验时启动）

碰撞的价值是让用户检验“接触后质量和动量怎样分配”等明确问题，或形成沙盒玩法。单纯展示太阳系轨道、学习常规公转、驾驶飞船，都不需要天体合并。本包只解释规定的简化规则，不能借此声称重现真实行星形成。

### S2.1 接触检测与事件

- 使用实验物理半径判定接触，与放大显示的球体尺寸分离。
- 处理高速跨步接触；采用连续检测或细分推进，并通过冻结的高速案例验证。
- 记录参与对象、接触时间、位置和碰撞前状态；同时发生多次接触的处理顺序必须确定。
- 首版只支持球形接触边界；不规则外观不会自动获得精确接触形状。

### S2.2 简化合并规则

- 首版仅支持完全非弹性合并，计算合并后的质量、质心位置和速度。
- 合并半径采用明确的体积/密度规则，记录机械能损失，不能宣称碰撞前后机械能不变。
- 记录角动量收支；若不模拟合并体自旋，明确相应角动量未进入可见自转模型，不冒充完整守恒演化。
- 碰撞效果服务于解释，不先追加碎片、冲击波、岩浆、地形重建等系统。

### S2.3 回放、恢复与验收

- 复用 S1 存档，补充事件前检查点、事件列表和按相同规则重新推进。
- 不通过负时间积分假装“撤销”；回到事件前状态后重新运行。
- 验收案例：正面、偏心、高速接触、同时多体接触及无接触掠过。核对质量、线动量、能量变化与事件顺序。
- **不做**：破碎、流体、潮汐撕裂、真实地质、生态灭绝预测和长时行星形成模拟。

## 6. S3：飞船与任务（可独立于 S1/S2 启动）

先确定是学习轨道机动、体验驾驶，还是做任务游戏；由此决定操控精度、辅助程度与任务反馈。现有天体历表可作为背景与引力来源；探测器可作为不反作用于天体的实体。无需允许用户修改地球，更无需先实现两颗星球合并。

### S3.1 无推力探测器与空间精度

- 新增有科学位置、速度和碰撞状态的探测器实体，先验证无推力轨道。
- 复用已有自由观察和天体跟随；只新增实体跟随、驾驶视角及必要的局部坐标精度支持。
- 全景可继续压缩距离用于导航；近距离驾驶采用可解释的物理距离，并明确切换。不得用宏观压缩坐标做引力飞行。
- 首版可采用探测器不反作用于天体的测试粒子近似，但必须记录该规则。
- 验收：无推力轨迹达到约定基准；全景/驾驶切换不改变实体状态，近景无严重抖动或穿入。

### S3.2 姿态、推力与燃料

- 定义推进方向、推力、干质量、燃料和耗尽后的行为；辅助驾驶与手动驾驶有明确区别。
- 根据推力与质量推进速度变化，正确处理耗尽时刻和暂停/恢复，不能按画面帧数施力。
- 加入机动预览及控制记录；先用简化姿态控制，真实刚体惯量与反作用轮不是首版条件。
- 验收：同样控制记录能在约定容差内重现，燃料不会变负，保存恢复无额外冲量。

### S3.3 三类任务与反馈

- 飞掠：到达目标附近指定距离区间并完成观察。
- 入轨：在指定天体附近达到明确的轨道条件并维持规定时间，不能只按“靠近了”判成功。
- 交会：对目标同时满足距离和相对速度条件；首版可用简化目标探测器。
- 每类先做一个单人训练任务，提供初始场景、操作引导、成功/失败条件和重新开始。
- 先利用合理的近目标初始条件，避免把长时间等待当作任务；不直接承诺完整地月往返或自动轨道规划。

### S3.4 任务存档与交付

- 保存飞船状态、控制记录、燃料、任务进度和事件版本；恢复不能重复结算任务。
- 飞船需要独立的目标表面/安全距离撞击判定；若 S2 已存在可复用检测基础，但不得以 S2 的天体合并功能作为前置。
- 完成三类任务、暂停、恢复、失败重试和回到真实观测的整条验收。
- **不做**：真实座舱全系统、着陆、精细地表、大气再入、空间站经营、多人联机。

## 7.1 人造航天器：三条不同路线

| 路线 | 用户要理解或完成什么 | 所需内容与验收 | 启动关系 |
| --- | --- | --- | --- |
| A 真实航天任务观察 | 看一颗人造卫星或探测器何时、如何围绕目标运行，与天然卫星有何不同 | 先挑少量代表任务；记录对象身份、任务名称、数据源、采集/更新时刻、有效期、坐标与模型，能定位、播放、看参数及来源；数据失效有提示 | 可由当前认知版独立扩展；不需要可驾驶飞船 |
| B 模拟卫星部署与运营 | 选目标轨道，在空间释放卫星，进行变轨并理解覆盖和寿命 | 探测器/卫星状态、入轨条件、推力或一次速度改变量、燃料与存档；先做一个可复现的近地轨道任务；覆盖、地面站、供电按需要后加 | 可复用 S3 的动力学与任务基础；无需修改地球或让天体碰撞 |
| C 地面火箭发射 | 从发射场起飞，经过级间分离和入轨，再部署卫星 | 需另建地面坐标、地球自转、推力曲线、质量与分级、气动/阻力、发射窗口、失败规则与验证案例 | 是单独的高成本模拟方向；不能把“在轨释放卫星”称为完整发射 |

路线 A 的具体轨道数据必须逐任务核查。近地人造卫星可评估 [CelesTrak GP/OMM 格式](https://celestrak.org/NORAD/documentation/gp-data-formats.php)及与其配套的传播模型；任务轨迹可评估 [NASA NAIF SPICE](https://naif.jpl.nasa.gov/) 或 [JPL Horizons 航天器资料](https://ssd.jpl.nasa.gov/horizons/manual.html)。这些来源的数据性质、适用对象和更新频率不同，不直接套用天然天体的历表管线；每个候选还要核查可用性和使用条款。JPL 明确提醒航天器轨迹不是实时传送，尤其近地轨道的未来预测需要及时更新，不能把过期轨迹标为“此刻真实位置”。

路线 B/C 是用户创建的**模拟任务**。其时间、轨道与真实任务资料分开展示。近地卫星采用的轨道根数传播与实验里的牛顿多体积分也要分开标识，不能把两套状态直接互换后宣称同等精度。

## 7.2 本轮盘点发现的其他候选缺口

| 类别 | 具体缺口 | 适合何时补 |
| --- | --- | --- |
| 地面与任务支持 | 发射场、地面站、通信视线与延迟、覆盖区域和测控 | 选择卫星运营、真实任务讲解或远距离探索时 |
| 在轨工程 | 空间站、交会对接、编队/星座、补给与轨道维护 | 有明确的人造设施或运营任务时；不等同于多画几个小球 |
| 空间碎片与寿命 | 失效卫星、碎片、离轨和再入的简化规则 | 要解释空间环境或形成运营风险玩法时；不生成虚假的逐片实时轨迹 |
| 行星际任务 | 探测器飞掠、重力助推、通信与能源约束 | 选择真实任务解读或深空驾驶时，逐任务核查轨迹区间 |
| 地表活动 | 进入大气、下降着陆、巡视器、限定地形与返回 | 在轨任务验收后另选场景；地表资产和物理要求独立 |
| 自然科学与观测 | 形成史、长期演化、从具体地点看天空 | 有清楚的学习问题和可追溯资料时；不把概念示意冒充当日实况 |

这是当前规划盘点，不声称列尽未来所有可能的航天或宇宙产品。每项都有独立启动条件，未选择时不进入本版交付倒计时。

## 8. 共用设计与数据规则

- **身份统一**：观测对象、实验对象、飞船、角色各有稳定 ID；记录它们的类别和父系统，不靠数组位置猜身份。
- **状态分开**：权威参考、物理实验、幻想世界有不同规则和存档；同一个三维外观不能隐去数据来源差别。
- **时间明确**：记录科学历元、实验推进时间和故事时间，切换时说明；不能把故事进度当作当日实况。
- **显示独立**：视觉放大、压缩距离、灯光、镜头不反向写入动力学状态；可见区域点云不能自动变成引力粒子。
- **按需精度**：每个支持的实验范围单独验证步长；近遇、推力与碰撞不能照搬当前 300 秒基准。
- **算力边界**：物理继续在 Worker 中执行，限制单批计算；不足时报告实际推进速度，不跳过必要物理步骤。
- **可恢复**：初始条件、当前快照、控制/编辑事件、算法与数据版本成套记录。跨设备复现按容差验收，不轻率承诺浮点逐位一致。
- **接口按所选方向增加**：选择 S1 才加实验与编辑命令，选择 S2 才加天体合并事件，选择 S3 则加探测器控制和任务；不先建设一个覆盖所有游戏的庞大框架。

## 9. 如何执行，怎样避免无限优化

先通过目标选择关口：具体用户与问题、现有功能不足的证据、需要模拟的行为、最小场景、成功判断。没有这些前提，S1/S2/S3 均保持候选。选定后，每阶段开始时冻结一页执行约定：用户故事、包含/不包含项、对象/场景数、数据有效期、测试设备、性能和数值误差门槛、验收案例、预计工作量。工期在这些条件明确后估算；本规划不凭空承诺日期。

每个工作包依次完成：实现 → 对照冻结标准验证 → 本地展示 → 记录已知限制 → 提交描述 → 明确发布范围。默认在本地开发和验证，发布后仅做线上核对，避免把线上页面当作开发环境。

阶段通过条件：约定案例可完成、阻断问题关闭、数值/规则说明齐备、存档能恢复、用户确认、远端版本可重建。每阶段只在收到实际问题时修复；美化、更多对象和新玩法进入候选池，不自动增加本阶段范围。

归档包含源码提交、数据和资产版本、规则版本、验收记录、已知限制及部署记录。发布可另设明确版本标签以便恢复；当前已有提交定位，本文不声称已创建新标签。

状态统一使用：**候选 → 已排期 → 实现中 → 已验证 → 待用户验收 → 已验收归档**。只写“已上线”不能替代验收，只有文档说明也不能计为功能实现。

## 10. 下一次实际启动的范围

下一次先确定**一个目标场景**，而不是默认进入 S1.1。例如：

- 想回答“公转速度变化为何影响轨道”：先试现有课程和参数解释；仍无法直观看出因果时，选 S1 的单变量地球速度实验。
- 想亲自驾驶探测器接近月球：选 S3 的无推力探测器与近景精度样机，再逐步加入推力和任务；不经过 S1/S2。
- 想知道人造卫星怎样运行：先选 O9/A 的真实任务展示；若想自己部署卫星，再选 O9/B 的模拟入轨；只有明确要从地面起飞，才评估 O9/C 的完整火箭发射。
- 想看两颗实验球体相遇后会怎样：明确需要简化合并，再先建 S1 的最小可复现实验，随后选 S2。

目标场景确定后才估算对应工作包与工期。当前仅整理候选规划，r09.12 的场景和验收状态不变。
