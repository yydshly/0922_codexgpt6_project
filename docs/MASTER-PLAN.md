# 太阳系观测站 · 产品总规划

版本：2026-09-25 / 总规划 v2.7，范围补正与交付顺序已整理，待用户验收。后续执行与范围变更以此总规划为主；近期更新记录不是总路线。

## 1. 最终要交付什么

目标是一款面向电脑浏览器的三维太阳系认知与观测产品：先看清太阳系的整体空间结构，再逐级观察区域、真实代表天体、家族和环境，理解它们怎样运动，以及太阳系在更大宇宙中的位置。每项可显示内容都能解释它是什么、位于哪里、怎样运行、数据从哪来、画面做了什么缩放或近似。

首版用户应能完成六件事：认识整体构成；区分真实距离与显示比例；跟随选定日期的真实对象；理解不同天体运行与主要天象；辨别实测依据、模型和视觉示意；沿观察路径往返并查看来源。

“完整”是本规划定义的主要类别、代表对象、观察闭环和来源覆盖，不是把所有已发现天体或未知对象逐个放进浏览器。也不以某个动态数量、九批图层、四批优化或提交次数宣布完成。

当前登记为 **52 个当前动态目标、27 颗选定卫星，另有 1 个独立历史案例**。R01/R02 已提交远端；R03 约定家族、双体与环代表，以及 R04 约定基础外观和结构代表已实现，本轮统一比例与近景修复一起交付，用户验收独立记录。后续为 R05–R09，不按批次数换算完成百分比。

## 5. 七个里程碑与 21 个工作包

这是整体工作分解，共 7 个里程碑、21 个待逐项确认验收的工作包。许多已有可复用成果，不等于 21 项全部从零开始，也不等于只需 21 次对话。工作包保留稳定编号，避免后续每轮重新定义下一步。

M0–M6 保留为工程里程碑分类，不再表示严格交付先后。当前按 R01–R09 九批执行：内部小天体 → 远缘对象 → 卫星与环 → 本体外观 → 环境联系 → 运动天象 → 全景与内部路线 → 宇宙背景 → 总验收。详见 [九批执行表](EXECUTION-PLAN.md)。

可交错工作：M1 台账与 M0 修复；M2 显示和 M3 离线数据准备；M4 可先使用已经验证的地月和巨行星对象。M6 的检查从各阶段开始持续执行，最后再做总验收；不把质量留到最后才考虑。

### M0 · 冻结现有基线

当前：已有基础，待集中验收。

交付价值：先把已经做出的能力变成可重复验收的稳定起点。

依赖：无；复用当前项目。

**M0.1 · 核对已交付范围**

范围：核对 52 个当前动态目标及 1 个历史案例、九批内容图层及现有目录；区分已发布和本地待验收。

完成标准：清单与运行结果一致，全部关键入口有验收记录。

**M0.2 · 清除阻断问题**

范围：检查加载失败、日期边界、家族近景遮挡、返回路径、空白画面与窄窗口；记录性能基准。

完成标准：启动、选日期、定位、返回、重试等关键路径无阻断；参考测试设备和数据版本已记录。

**M0.3 · 形成可回退版本**

范围：完成旧四批中的最后一批验收，保留源码、资源、验证报告与部署记录。

完成标准：用户验收稳定基线；能从明确提交重建和回退。

**M1.1 · 元素覆盖台账**

范围：以 20 类核心主题登记真实对象、区域、现象；分别维护数据、显示、交互、验证、发布状态。

完成标准：每项有当前状态、缺口、归属里程碑、数据依据；没有只写“完成”的笼统项。

**M1.2 · 统一供数与显示合同**

范围：统一身份、父系统、时刻、坐标、单位、中心/质心、几何/视位置、数据范围与证据类型。

完成标准：新对象不靠固定数组数量接入；在全景、目录、近景和参数中身份一致，缺失数据不造值。

**M1.3 · 冻结首版样本与资源预算**

范围：为 M2–M5 冻结对象名单、来源/许可、有效日期、采样误差预算、按需加载与画质分级方案。

完成标准：每个候选可复现获取数据；无法满足的候选有替代或明确范围变更，不悄悄删项。

范围：导入经过质量筛选的恒星星表子集，按星位、星等绘制并点选查询；与装饰星点分开。

完成标准：背景主要星点可追溯到星表；坐标方向经独立样本验证；没有距离的数据不伪造空间深度。

**M2.2 · 完整宏观区域组合**

范围：统一主带、特洛伊群、半人马族、柯伊伯带、散射/离散区域、尘埃、日球层、奥尔特云的体积与标注层次。

完成标准：同一全景均有入口和图层；侧视能说明实际或模型厚度；随机点与真实成员视觉可区分。

**M2.3 · 跨尺度呈现标准**

范围：统一全景/区域/系统/本体的比例提示、标注优先级、选中态、光照与定位；修正遮挡和小球误识。

完成标准：真实比例与解释性缩放切换有明确提示；球体、轨道、参考线和现象不互相冒充。

### M4 · 补齐运动关系与空间现象

当前：部分原理示意已有，事件与关系演示待补。

交付价值：从“有哪些东西”推进到“它们怎样运行和相互作用”。

依赖：M1；涉及的真实对象通过 M3 或现有基线验证。

**M4.1 · 运行关系课程**

范围：完成自转/公转、月相/季节、潮汐锁定、轨道共振四组对照；分别标明观测关系和模型示意。 增加共轨或准卫星参照系对照案例。

完成标准：四组均可分步、暂停、重播和返回；运行比例有依据；潮汐力/共振不是凭动画速度假装求解。

**M4.2 · 日月食与遮掩**

范围：先验证至少一个日食、一个月食案例；再接入卫星遮掩示例，区分空间几何与地面可见条件。

完成标准：事件日期和关键时刻与权威资料核对并报告偏差；观察地点与时区明确；不以几何对齐直接宣称可见。

**M4.3 · 环境与物质联系**

范围：串联太阳活动→太阳风→地球环境、彗星/碎屑→流星、尘埃→黄道光，并以木星环境作对照。 明确补行星际磁场、电流片、光与粒子辐射、中性粒子和喷流补给环系；不可见环境采用可关闭解释层。

完成标准：三条因果讲解均有可控示意与来源；真实日期和示意进度分开；黄道光、流星雨不冒充当天实况。

## 6. 数据如何成为产品

来源获取 → 保留原始快照与许可 → 对象身份和单位检查 → 统一时间/坐标/参照中心 → 生成分月或分区包 → 用独立样本检查 → 统一供数接口 → 场景/参数/图鉴共用 → 用户入口和来源说明 → 发布验收。

| 数据类型 | 首选来源与处理 | 产品显示边界 |
| --- | --- | --- |
| 太阳系位置/速度 | JPL Horizons 或 NAIF SPK；固定版本、有效期、中心和单位；本地分包、验证插值 | 几何状态与视位置分开；不能因播放越界自动伪造历表 |
| 半径/质量/自转/姿态 | JPL 参数表、NAIF PCK 等；记录参考值和近似 | 不把平均半径当精密形状，不把纹理自转当实时云层 |
| 小天体 | SBDB 身份和轨道解、Horizons 状态；保留轨道解质量与有效日期 | 数据插值误差与轨道本身不确定性分别说明 |
| 恒星 | 固定版本的 ESA Gaia 等目录子集；质量筛选、坐标转换、历元和自行处理 | 缺失/低质量视差不直接倒数成可靠距离；二维星位与三维可信样本分层 |
| 纹理和形状 | 优先 NASA/ESA/PDS 等许可可用资料；保留来源与加工记录 | 实测形状、静态贴图、程序纹理与艺术示意分别标识 |
| 环境/区域 | NASA 等科学资料与研究；维护参数范围、不确定性和示意采样规则 | 不把示意密度、粒子数或固定球壳称为实测 |
| 天象事件 | 权威事件表、观测几何和必要的光行时/地点处理 | 展示事件窗口和误差；不作航天导航或空间天气预测承诺 |

每次数据升级记录生成时间、来源版本、覆盖期、单位、校验值、插值方法、独立检查点及最大误差。采样间隔不一刀切：先测再加密。核心既有插值 ≤1 km 目标不等于所有新对象的总位置准确度；高不确定的小天体与恒星必须报告自己的误差。

技术结构继续分离：资料目录、状态供数、物理 Worker、显示转换、场景图层、观察上下文、知识内容和验证。新显示元素不会自动进入物理积分；系统质心与展开卫星的质量不可重复计算。真实观测、原理示意和未来用户实验分别管理时钟与状态。

首版运行时以本地数据包为主。按月份/对象/层级加载、缓存和取消过期请求；低画质降低粒子、纹理与标注密度，不修改真实坐标。增加对象前先核对包体、内存和相机精度预算；必要时使用以相机/目标为原点的显示变换。

## 7. 稳定的完成标准与优先级

P0 阻断：错误科学标注、对象或时刻不一致、无法启动/返回/加载恢复。立即处理，不等新内容阶段。

P1 主线：20 类元素覆盖缺口与六条完整观察路线，按 M1–M5 推进。

P2 深化：更多同类成员、更高分辨率表面、更多事件；仅在核心覆盖之后扩展，不挤掉缺失类别。

P3 长期：游戏、探测器、实时空间天气、长期宇宙演化与完整相对论模型等单独决策。

每个工作包交付证据：代码/数据变化、来源与边界、可操作入口、关键验证、已知限制、提交描述、本地验收位置。状态经过“已实现 → 已验证 → 待用户验收 → 已发布”记录；发布与用户验收允许分开，但不混称完成。

认知版整体退出条件：20 类主题均达到约定层级；六条 3–5 步路线走通；所有动态样本通过各自数据门槛；主要视图的视觉和性能达到冻结设备预算；关键异常流程通过；发布文档齐全；用户确认接受当前覆盖和已知限制。

性能指标是待验证目标：M0 冻结参考设备和浏览器，M6 在其上测量。默认以 1440×900、限定 DPR 的桌面场景为起点，典型全景目标 ≥30 fps；真实高密度场景需要分层显示。没有测量之前不宣称达标。资源检测包括缓存预热后的连续 20 次切换、几何/纹理数量与可测内存趋势，而不是承诺所有硬件同一帧率。
