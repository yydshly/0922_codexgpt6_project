# 太阳系观测站 · 产品总规划

版本：2026-09-24 / 总规划 v1，待用户评审。后续执行与范围变更以此总规划为主；近期更新记录不是总路线。

## 1. 最终要交付什么

目标是一款面向电脑浏览器的三维太阳系认知与观测产品：先看清太阳系的整体空间结构，再逐级观察区域、真实代表天体、家族和环境，理解它们怎样运动，以及太阳系在更大宇宙中的位置。每项可显示内容都能解释它是什么、位于哪里、怎样运行、数据从哪来、画面做了什么缩放或近似。

首版用户应能完成六件事：认识整体构成；区分真实距离与显示比例；跟随选定日期的真实对象；理解不同天体运行与主要天象；辨别实测依据、模型和视觉示意；沿观察路径往返并查看来源。

“完整”是本规划定义的主要类别、代表对象、观察闭环和来源覆盖，不是把所有已发现天体或未知对象逐个放进浏览器。也不以某个动态数量、九批图层、四批优化或提交次数宣布完成。

## 2. 产品范围分三层

| 层级 | 首版范围 | 完成边界 |
| --- | --- | --- |
| 核心：真实太阳系认知版 | 本文 20 类主题、通过准入的代表对象、六条学习路线和科学/体验验收 | M0–M6 对应验收项完成，用户验收确认 |
| 背景：太阳系在宇宙中的位置 | 恒星星表、邻近恒星三维样本、银河系与邻近星系尺度衔接 | 有限目录与概念模型，不宣称精确重建整个宇宙 |
| 后续：可干预、可扮演的世界 | 参数沙盒、碰撞、飞船与任务、仙侠等产品分支、更多宇宙专题 | 独立立项、预算与验收，不阻塞核心认知版 |

保留当前 2026—2027 年作为基础观测窗口；历史事件、长周期/星际对象若需其他日期，必须明确独立时间范围、入口和切换提示，不能在日期越界时静默外推。

## 3. 现在究竟在哪里

已实现基础包括：太阳、八大行星、21 颗选定卫星、5 颗矮行星、灶神星、哈雷与 67P，合计 38 个不同动态目标；主观测 32 个、宏观额外 6 个，图鉴不另行相加。九批内容图层和 17 项全景目录已形成。

结构、太阳风、尘埃、磁层等多为有来源的示意。背景星点尚非真实星表。十体引力实验是独立基准，不等于所有 38 个对象参与引力积分。

规划建立时快照：远端至 `1ff50ba`，本地第三批路径至 `01d830c`。后续集中交付包含观察路径、规划、学习与验收清单，实际提交和部署以建设记录及 GitHub Actions 为准。本次新增的是总规划和阅读入口，下面列出的未来能力不因写入规划而变成已实现。

原先“四批收尾”的映射：视觉整理、尺度比较、全景路径是既有产品基础，对应 M2.3、M5.3 的部分基础；其第四批仅对应 M0 的既有版本验收。它们全部做完，也不代表 M0–M6 的整个产品路线完成。

### 状态必须分开记录

- 数据依据：真实历表/观测目录、文献参考参数、近似模型、结构示意、推断或暂无资料。
- 产品能力：有资料 → 有画面 → 可操作 → 已验证 → 已发布 → 用户验收。
- 交付证据：绑定工作包、文件/数据版本、测试或截图、提交、部署和用户验收记录。

本文“已有基础”只描述基础；没有任何里程碑在本次规划中预先标为整体验收完成。不计算虚假的总完成百分比。网页覆盖表现已绑定实际模块、数据版本、可用入口和已知验证范围，见 CONTENT-COVERAGE.md；用户逐类验收与总验证仍待完成。

## 5. 七个里程碑与 21 个工作包

这是整体工作分解，共 7 个里程碑、21 个待逐项确认验收的工作包。许多已有可复用成果，不等于 21 项全部从零开始，也不等于只需 21 次对话。工作包保留稳定编号，避免后续每轮重新定义下一步。

主顺序：M0 既有基线 → M1 范围和数据合同 → M2 宏观整体 → M3 代表成员 → M4 关系现象 → M5 宇宙定位和完整导览 → M6 正式验收。

可交错工作：M1 台账与 M0 修复；M2 显示和 M3 离线数据准备；M4 可先使用已经验证的地月和巨行星对象。M6 的检查从各阶段开始持续执行，最后再做总验收；不把质量留到最后才考虑。

### M0 · 冻结现有基线

当前：已有基础，待集中验收。

交付价值：先把已经做出的能力变成可重复验收的稳定起点。

依赖：无；复用当前项目。

**M0.1 · 核对已交付范围**

范围：核对 38 个动态目标、九批内容图层、17 个目录入口与三个观察优化批次；区分已发布和本地待验收。

完成标准：清单与运行结果一致，全部关键入口有验收记录。

**M0.2 · 清除阻断问题**

范围：检查加载失败、日期边界、家族近景遮挡、返回路径、空白画面与窄窗口；记录性能基准。

完成标准：启动、选日期、定位、返回、重试等关键路径无阻断；参考测试设备和数据版本已记录。

**M0.3 · 形成可回退版本**

范围：完成旧四批中的最后一批验收，保留源码、资源、验证报告与部署记录。

完成标准：用户验收稳定基线；能从明确提交重建和回退。

### M1 · 建立全量内容与数据规则

当前：20 类覆盖清单已关联模块、数据版本和现有入口；供数统一、样本预算与逐类验收仍待完成。

交付价值：以后任何新增内容都能在同一总图上找到位置。

依赖：M0.1；可与 M0 修复交错推进。

**M1.1 · 元素覆盖台账**

范围：以 20 类核心主题登记真实对象、区域、现象；分别维护数据、显示、交互、验证、发布状态。

完成标准：每项有当前状态、缺口、归属里程碑、数据依据；没有只写“完成”的笼统项。

**M1.2 · 统一供数与显示合同**

范围：统一身份、父系统、时刻、坐标、单位、中心/质心、几何/视位置、数据范围与证据类型。

完成标准：新对象不靠固定数组数量接入；在全景、目录、近景和参数中身份一致，缺失数据不造值。

**M1.3 · 冻结首版样本与资源预算**

范围：为 M2–M5 冻结对象名单、来源/许可、有效日期、采样误差预算、按需加载与画质分级方案。

完成标准：每个候选可复现获取数据；无法满足的候选有替代或明确范围变更，不悄悄删项。

### M2 · 补齐宏观整体与真实星空

当前：区域骨架已有，真实星表与统一层次待补。

交付价值：先让用户看懂整体空间中究竟有什么。

依赖：M1 数据合同与来源准入。

**M2.1 · 真实星空背景**

范围：导入经过质量筛选的恒星星表子集，按星位、星等绘制并点选查询；与装饰星点分开。

完成标准：背景主要星点可追溯到星表；坐标方向经独立样本验证；没有距离的数据不伪造空间深度。

**M2.2 · 完整宏观区域组合**

范围：统一主带、特洛伊群、半人马族、柯伊伯带、散射/离散区域、尘埃、日球层、奥尔特云的体积与标注层次。

完成标准：同一全景均有入口和图层；侧视能说明实际或模型厚度；随机点与真实成员视觉可区分。

**M2.3 · 跨尺度呈现标准**

范围：统一全景/区域/系统/本体的比例提示、标注优先级、选中态、光照与定位；修正遮挡和小球误识。

完成标准：真实比例与解释性缩放切换有明确提示；球体、轨道、参考线和现象不互相冒充。

### M3 · 补齐代表成员与天体家族

当前：已有 38 个动态目标，更多代表对象待接入。

交付价值：把只有类别或点云的内容落到可观察的真实对象。

依赖：M1 的数据准入；显示采用 M2 标准。

**M3.1 · 小天体代表集**

范围：近地小行星、木星 L4/L5 特洛伊群、半人马族、离散天体、长周期彗星、星际访客各选代表；每类至少一例，L4/L5 分别一例。

完成标准：冻结名单中的对象均可查来源、选择、定位、按有效日期运行；未获可靠数据的类别明确阻塞。

**M3.2 · 扩展卫星与环系**

范围：优先冥王星另外四颗卫星，再选至少一个其他矮行星卫星系统；细化四大巨行星环、代表性小天体环的资料与示意。

完成标准：家族父子关系、时间与相对参数一致；至少新增一个矮行星卫星系统；环说明参考范围与增强方式。

**M3.3 · 天体外观与参数一致性**

范围：逐一检查太阳、八大行星及核心卫星的尺寸、自转、倾角、昼夜、纹理、大气和云层；不同表面类型明确区分。

完成标准：所有核心对象具有统一参数卡和外观说明；未知表面采用标记清楚的示意，不画成实拍；显示放大不改变物理参数。

### M4 · 补齐运动关系与空间现象

当前：部分原理示意已有，事件与关系演示待补。

交付价值：从“有哪些东西”推进到“它们怎样运行和相互作用”。

依赖：M1；涉及的真实对象通过 M3 或现有基线验证。

**M4.1 · 运行关系课程**

范围：完成自转/公转、月相/季节、潮汐锁定、轨道共振四组对照；分别标明观测关系和模型示意。

完成标准：四组均可分步、暂停、重播和返回；运行比例有依据；潮汐力/共振不是凭动画速度假装求解。

**M4.2 · 日月食与遮掩**

范围：先验证至少一个日食、一个月食案例；再接入卫星遮掩示例，区分空间几何与地面可见条件。

完成标准：事件日期和关键时刻与权威资料核对并报告偏差；观察地点与时区明确；不以几何对齐直接宣称可见。

**M4.3 · 环境与物质联系**

范围：串联太阳活动→太阳风→地球环境、彗星/碎屑→流星、尘埃→黄道光，并以木星环境作对照。

完成标准：三条因果讲解均有可控示意与来源；真实日期和示意进度分开；黄道光、流星雨不冒充当天实况。

### M5 · 完成从太阳系到宇宙的认识路径

当前：已有邻域概念图，空间坐标与完整导览待补。

交付价值：理解太阳系所在的位置，同时知道每层尺度的证据边界。

依赖：M2 星空；M3/M4 对应内容。

**M5.1 · 邻近恒星三维样本**

范围：选择至少 20 个通过质量检查的邻近恒星/系统样本，展示方向、距离、误差和太阳的位置。

完成标准：有距离依据的样本才进入三维层；双星/多星层级不重复计数；视差与距离误差明确。

**M5.2 · 银河系与更大尺度**

范围：串联太阳系→邻星→银河系→邻近星系；说明各尺度的方位、形态、距离和不确定性。

完成标准：切换保留尺度说明和明确返回入口；银河形态模型与真实星位分开；不把其他星系放进太阳系轨道。

**M5.3 · 六条完整观察路线**

范围：交付整体边界、地月、巨行星家族、小天体、太阳风与地球、太阳系在宇宙中的位置六条路线。

完成标准：每条 3–5 步，有观察目的、来源提示、当前状态与逐级返回；主观测、全景、独立详解的跳转一致。

### M6 · 太阳系认知版正式验收

当前：待前述里程碑交付后集中验收。

交付价值：明确这一版何时真正完成，而不是无限追加元素。

依赖：M0–M5 对应验收项关闭。

**M6.1 · 科学与数据总验收**

范围：复核坐标/时间/单位/中心、插值检查点、姿态近似、事件案例与来源；复用并更新十体验证报告。

完成标准：原核心插值 ≤1 km 目标继续核验；新类别独立批准误差预算；区分数值误差、模型差异和观测不确定性。

**M6.2 · 体验与性能总验收**

范围：在冻结的桌面设备、浏览器与分辨率检查全景、密集标签、近景、跨月、离线/失败重试和连续切换。

完成标准：参考桌面典型全景目标 ≥30 fps；连续 20 次跨模块切换无持续资源增长或上下文丢失；未达标先分级降载并复测。

**M6.3 · 版本交付与用户验收**

范围：交付代码、来源清单、数据版本、说明、验证报告、内容缺口与发布记录，完成本地验收后发布。

完成标准：20 类核心主题达到各自约定层级；六条路线可走通；无关键阻断；用户确认验收，才称“认知版完成”。

## 6. 数据如何成为产品

来源获取 → 保留原始快照与许可 → 对象身份和单位检查 → 统一时间/坐标/参照中心 → 生成分月或分区包 → 用独立样本检查 → 统一供数接口 → 场景/参数/图鉴共用 → 用户入口和来源说明 → 发布验收。

| 数据类型 | 首选来源与处理 | 产品显示边界 |
| --- | --- | --- |
| 太阳系位置/速度 | JPL Horizons 或 NAIF SPK；固定版本、有效期、中心和单位；本地分包、验证插值 | 几何状态与视位置分开；不能因播放越界自动伪造历表 |
| 半径/质量/自转/姿态 | JPL 参数表、NAIF PCK 等；记录参考值和近似 | 不把平均半径当精密形状，不把纹理自转当实时云层 |
| 小天体 | SBDB 身份和轨道解、Horizons 状态；保留轨道解质量与有效日期 | 数据插值误差与轨道本身不确定性分别说明 |
| 恒星 | 固定版本的 ESA Gaia 等目录子集；质量筛选、坐标转换、历元和自行处理 | 缺失/低质量视差不直接倒数成可靠距离；二维星位与三维可信样本分层 |
| 纹理和形状 | 优先 NASA/ESA/PDS 等许可可用资料；保留来源与加工记录 | 实测形状、静态贴图、程序纹理与艺术示意分别标识 |
| 环境/区域 | NASA 等科学资料与研究；维护参数范围、不确定性和示意采样规则 | 不把示意密度、粒子数或固定球壳称为实测 |
| 天象事件 | 权威事件表、观测几何和必要的光行时/地点处理 | 展示事件窗口和误差；不作航天导航或空间天气预测承诺 |

每次数据升级记录生成时间、来源版本、覆盖期、单位、校验值、插值方法、独立检查点及最大误差。采样间隔不一刀切：先测再加密。核心既有插值 ≤1 km 目标不等于所有新对象的总位置准确度；高不确定的小天体与恒星必须报告自己的误差。

技术结构继续分离：资料目录、状态供数、物理 Worker、显示转换、场景图层、观察上下文、知识内容和验证。新显示元素不会自动进入物理积分；系统质心与展开卫星的质量不可重复计算。真实观测、原理示意和未来用户实验分别管理时钟与状态。

首版运行时以本地数据包为主。按月份/对象/层级加载、缓存和取消过期请求；低画质降低粒子、纹理与标注密度，不修改真实坐标。增加对象前先核对包体、内存和相机精度预算；必要时使用以相机/目标为原点的显示变换。

## 7. 稳定的完成标准与优先级

P0 阻断：错误科学标注、对象或时刻不一致、无法启动/返回/加载恢复。立即处理，不等新内容阶段。

P1 主线：20 类元素覆盖缺口与六条完整观察路线，按 M1–M5 推进。

P2 深化：更多同类成员、更高分辨率表面、更多事件；仅在核心覆盖之后扩展，不挤掉缺失类别。

P3 长期：游戏、探测器、实时空间天气、长期宇宙演化与完整相对论模型等单独决策。

每个工作包交付证据：代码/数据变化、来源与边界、可操作入口、关键验证、已知限制、提交描述、本地验收位置。状态经过“已实现 → 已验证 → 待用户验收 → 已发布”记录；发布与用户验收允许分开，但不混称完成。

认知版整体退出条件：20 类主题均达到约定层级；六条 3–5 步路线走通；所有动态样本通过各自数据门槛；主要视图的视觉和性能达到冻结设备预算；关键异常流程通过；发布文档齐全；用户确认接受当前覆盖和已知限制。

性能指标是待验证目标：M0 冻结参考设备和浏览器，M6 在其上测量。默认以 1440×900、限定 DPR 的桌面场景为起点，典型全景目标 ≥30 fps；真实高密度场景需要分层显示。没有测量之前不宣称达标。资源检测包括缓存预热后的连续 20 次切换、几何/纹理数量与可测内存趋势，而不是承诺所有硬件同一帧率。

## 9. 接下来怎样执行，怎样知道还剩多少

本次先交付总规划供用户评审，不把写出未来模块误记为实现。建议首个执行包是 M0.1 + M1.1：将现有能力和 20 类元素逐项绑定模块、数据版本、完成层级和缺口；同时集中清理 M0.2 的阻断。随后优先 M2 宏观整体和真实星空，再按路线推进 M3–M5。

进度以“里程碑状态 + 工作包验收 + 元素层级”三种视角查看。九批开关仍只控制已经实现的内容；近期四批优化保留为历史子项目。旧《扩展实施路线》的工程接口和游戏分支作为参考细分，优先顺序服从本总规划。
