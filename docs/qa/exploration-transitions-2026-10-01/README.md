# 六站航程的离开、取消与故事衔接

验证日期：2026-10-01。状态：本地生产预览，未提交、未推送。

## 修正的问题

1. 六站航程返回全景或按 Esc 时，原先直接卸载飞船场景，尚未下载的到达记录、笔记和讲解随之清空。进入故事、独立练习或异常后重开，也缺少在切换当下保存记录的入口。
2. 故事发射与单站驾驶页原按钮写着「退出故事」，实际返回新的六站航程；现在明确显示「返回探索（新航程）」。
3. 进入故事后，六站界面卸载，底层宏观全景的 active / inert 条件却没有包含故事状态。现在故事期间停止全景绘制并隔离交互，返回后恢复。

## 本次行为

- 六站里的返回全景、进入独立练习、进入故事和异常后重开，先暂停并显示切换去向、本次实际记录与清空范围。
- 提示中可下载 Markdown 或 JSON。下载的是打开提示时的静态快照，不是可恢复存档；只提示「已请求下载」，由用户在浏览器下载列表确认文件。
- 取消或在提示内按 Esc，恢复先前运行／暂停状态；主动观察停留、当前位置、速度、推进剂、路线、到达与笔记保留。接触或显示错误时不能通过取消恢复运行。
- 提示打开时背景控件 inert，驾驶输入不能接管；默认焦点在取消，Tab 和 Shift+Tab 在提示里循环。
- 确认以后才执行切换或重开。故事、独立练习和新的六站航程仍有各自的初始状态，没有冒充同一载具从地面连续进入轨道。

## 验证结果

- 16 个相关测试文件、124 项通过；生产构建、规划文档同步和 `git diff --check` 通过。既有打包体积警告没有作为构建失败处理。
- 主流程 [checks.json](checks.json)：23 项通过，未捕获运行异常或控制台错误。
- 移动中取消 [moving-checks.json](moving-checks.json)：5 项通过，未捕获运行异常或控制台错误。
- 共 28 项有效浏览器检查。桌面 1440 × 1000、窄窗口 390 × 844 截图已查看。

主流程由实际自动驾驶抵达教学卫星，打开三个部件介绍并保存一份笔记。分别检查运行中和暂停中的取消、下载与焦点循环；随后实际按 W 向卫星推进，触及保守接触范围，核对取消重开仍保留失败状态，确认重开才清空旧记录。没有修改飞船内部状态或注入虚构到达记录。

故事部分进入发射场核对返回去向，再走「跳过观摩 → 驾驶准备 → 单站驾驶」，检查返回会开启新航程、背景全景持续 inert。另行进入独立练习，再确认返回全景恢复交互。本批没有重新运行完整发射或完整六站往返；这两段沿用原有验证，飞行动力学没有修改。

移动复查在自动飞行速率大于 1 m/s 时打开提示，核对非零速度、时间、燃料及余程冻结；提示里的驾驶键不接管。取消后实际时间和路程继续增加，目的地与余程不变、推进剂不恢复。原先已暂停的移动飞船取消后仍保持原速度与暂停状态。
