# 载人任务逻辑与异常场景复核

2026-10-01，本地 `crew-earth-3`。本轮修复控制设备可用性、首次接地和完成判定；保留正常教学故事的目的与原有精度。尚未提交或部署。

## 已修复的实际缺陷

| 问题 | 原行为 | 本轮结果 |
| --- | --- | --- |
| 关机仍有推力矢量控制 | 二级点火前 3 秒没有推力，仍产生主动制导力矩 | 力矩能力随实际推力建立；关机时为零，继承角速度继续转动 |
| 只按参考点 2 m 判接地 | 大约 60° 倾斜也可能被判为成功，实体已先碰地 | 共用返回几何，检测支脚角点和舱体包络首次触地；检查接地点速度、倾角、角速率及支脚部署 |
| 支脚动画掩盖失败 | 支脚依参考点高度拟合地面，未对应可靠物理判定 | 仅在已通过检查的小倾角接地中压缩，不伸长超出部署尺寸；失败保留真实倾斜状态 |
| 失败后质量/外形丢失 | 阶段变 failed 后不再计入仍连接的火箭 | 连接状态独立于任务阶段；质量、外形与存档保持一致 |
| 回收条件不完整 | 接地等待 3 秒即可记 complete | 还要求有效观察记录、合格接地记录、地面承载、已停稳的速度和姿态 |
| 阶段时间不对应状态 | 积分后状态记录为积分前时间；接地截断却继续完整步时钟 | 积分后的事件记步末时间；首次触地位置、姿态、速度与时钟停在同一事件时刻 |
| 失败说明误导 | 默认方向说明声称返回舱已在地面停稳 | 明确说明计算因条件不足停止，保留失败瞬间而非安全支撑 |
| 被动稳定受无燃料喷口影响 | 有些饱和组合中，不可用的喷口会降低被动力矩 | 先检查主动控制燃料，空气/支撑的独立恢复力矩仍可发挥作用 |

开伞判据直接从当前状态计算动压，不再依赖缓存值。分离时清除已经结束的控制力矩读数，保留真实姿态与角速度；离台解除约束时立即清除发射台作用力，避免离台画面仍声称地面在托住火箭。回收按钮与实际检查共用同一判定，无法从界面绕过。

## 教学规则与物理参照

首次接地检查：支脚已展开、舱体未先触地、倾角≤15°、角速率≤5°/s，接地点垂直速度≤3 m/s、水平≤5 m/s。速度含返回舱角运动在接地点产生的速度。之后采用原有 0.8 秒缓冲；至少检查 3 秒，倾角≤5°、角速率≤0.01 rad/s、相对地面速率≤0.1 m/s 且仍有地面支撑才能回收。**这些数值均为原创教学阈值，不是实飞着陆或人体安全标准。**

[NASA Rocket Control](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/rocket-control/)说明推力矢量控制通过改变发动机推力相对于质心的方向产生力矩。因此本模型未配置火箭独立姿态喷口时，不能在主发动机关机期间继续凭空产生该主动控制力矩。这里只采用受推力约束的等效制导力矩，未建模实际喷管偏转及其侧向分力。

[NASA Crew Module](https://www.nasa.gov/reference/crew-module/)提供返回舱自带反作用控制设备的结构参照；本项目返回舱独立资源、喷口与惯量参数仍为原创。上述 NASA 来源没有提供本项目的接地阈值。

支脚与舱体使用同一个三维姿态和局部切平面；舱体是保守旋转包络，不是逐三角形碰撞求解。支脚四角首先触地时，其余脚可以暂时悬空，之后由原有缓冲/支撑恢复模型逐渐承载；没有瞬间把整船扶正。

## 验证与复现

- [完整任务](nominal-result.json)：从地面到观察、返回与回收的当前模型结果。
- [姿态检查](attitude-checks.json)、[方向检查](direction-checks.json)、[返回几何检查](return-checks.json)：均使用同一版本结果。
- [故障与边界检查](safety-checks.json)：60° 倾斜、倒置舱体、高速垂直/水平接地、旋转接地、失败火箭质量、缺少观察记录等受控注入；异常夹具不表示正常任务发生了这些故障。
- [浏览器检查](browser-checks.json)：正常阶段恢复、返回读数、失败模型、条件提示、旧版存档拒绝、连续回收及无运行异常。
- [生产工作线程](production-worker-check.json)：实际构建从地面运行到完成；明显转姿发布状态并降速，不跳过滑行/再入阶段。
- [最终构建交接检查](production-boundaries-check.json)：解除约束后地面力为零，二级滑行没有主动制导力矩，飞船分离后清除火箭力矩；各事件与状态时钟一致。
- [验证汇总](verification.json)：全量测试、最后的相关回归、51 项浏览器检查和本地发布状态。

全项目 145 个测试文件 / 764 项测试通过，包含新增 13 项故障/边界回归；使用两个测试进程、30 秒单测超时。构建与文档同步检查通过，保留既有大体积主包提示。五项任务验证通过；正常接地点垂直速度约 1.034 m/s、水平约 0.028 m/s、倾角约 0.0115°，角速率约 0.00272°/s。完整姿态单步变化最大约 0.688°，没有提升物理步长或精度要求。

最后补充分离/离台的读数清理后，相关 2 个文件 / 13 项完整任务与姿态测试再次通过，并检查最终生产构建的三个交接边界。浏览器共 51 项检查通过，运行异常为零；完整任务还在实际生产工作线程中从头推进到完成。

浏览器使用独立无界面 Chrome 配置与软件渲染，隔离用户浏览器和存档；检查视觉/操作正确性，不据此推断用户电脑的实际 GPU 帧率。浏览器阶段截图使用完整任务产生的检查点；失败截图明确为故障注入。

用 `node node_modules/tsx/dist/cli.mjs scripts/validate-crew-mission.ts` 先生成基准，之后同样运行 `validate-crew-attitude.ts`、`validate-crew-directions.ts`、`validate-crew-return.ts`、`validate-crew-safety.ts`。本轮五个脚本的报告写入此目录，临时浏览器夹具在 `.cache`；旧版验证目录保留历史结果。

## 剩余边界与可选优化

本轮覆盖的正常任务和故障检查没有待修复的阻断问题，不表示所有异常均已覆盖。以下为已声明的模型边界，不作为持续延期的理由：

1. 标量惯量、气动/伞吊挂与地面恢复力矩、零海拔陆地和无风大气均为教学近似；未做完整三轴刚体、多点摩擦或伞绳弹性求解。
2. 热流不等于材料或舱内温度；未验证烧蚀、结构破坏、乘员生理、生命保障与救援。因此完成文案明确为教学流程检查通过。
3. 平台预置为邻近共轨教学目标，未求真实发射窗口、完整交会或对接；分离级与服务舱不再跟随主船，但其后续轨迹尚未单独接入。
4. 当前构建主包约 1.69 MB（gzip 约 520 kB），存在既有分包体积提示。可后续按模块拆分首屏资源并测冷启动；本轮未修改资源加载架构，不把软件渲染截图当作性能测试。

如继续扩展，可独立选择「分离部件去向可视化」「有风和备份伞的返回决策」「平台交会/对接」之一，各自有明确验收终点。本轮不自动扩大这些能力。

存档版本升为 `crew-earth-3`。v1/v2 旧载人存档会明确拒绝，当前任务不会被覆盖；可保留下载记录，从地面重开新版。既有太阳系、无人卫星任务的存档不受影响。
